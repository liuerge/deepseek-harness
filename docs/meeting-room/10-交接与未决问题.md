## 目标

把"会议室"做成基于 DSH 的产品：用户给一个目标，主助手拆解、开会、调度角色 Agent、交付，用户只做决策与验收。核心差异化是会议治理（独立首轮、争议台账、终审发布）与任务验收，不是重新发明对话界面。

## 形态决策

已定 **B：Bundle 产品**。DSH 作底座，会议室以自有 bundle + 桌面外壳发布，内部仍分三层：

1. `packages/experimental/meeting-room` — host 插件（会议服务、`meeting_start`、审批前置、SQLite 索引）
2. `packages/experimental/client-ui-meeting-room`— client 插件（`sidebar.panellist` + `main` 槽位）
3. `packages/experimental/meeting-room-bundle`— 组合层

改上游的优先顺序：插件 → bundle 组合 → fork 内补丁 → 才考虑 fork 核心。**所有改动只落在自己的 fork，不动上游仓库**；上游发版后做一次同步迭代。

## 环境约束（踩过的坑）

- **Gitea 在 WSL 里**，只监听 `[::1]`；Windows 侧靠 `C:\Users\nice\gitea-tunnel.cmd`（用户态转发，每次连接重取 WSL IP）。`netsh portproxy` 在这台机器上失效，不要走那条路。会话重启后需要重新运行该脚本。
- **代理**：本地 `127.0.0.1:7890` 可用，但 Node 原生 `fetch` 默认不读环境变量，需要 `NODE_USE_ENV_PROXY=1`。
- **`pnpm run <script>` 会做依赖校验**，node_modules 与锁文件不一致时会重新安装并可能删掉手工链接；门禁脚本建议直接 `node_modules/.bin/tsx scripts/<gate>.ts`。
- **`xlsx@0.20.3`** 来自 `cdn.sheetjs.com` 绝对地址，镜像不覆盖，网络差时需要本地 tarball 兜底；改完锁文件后记得还原。
- **桌面 `dev:desktop`** 卡在 `preparePrimaryRuntime` 下载，即使加了代理也只到 57MB 就停；`launchElectron` 未执行过。
- 中文 JSON 通过 shell 直接传参会被截坏（`invalid UTF-8 within "/title"`），用文件或 Node 脚本发送。

1. 准备隔离的 `DSH_HOME` 与 web profile：`$DSH_HOME/profiles/web/package.json` 的 `dsh.profile.bundles` 加入 `@deepseek-ai/dsh-meeting-room-bundle`。
