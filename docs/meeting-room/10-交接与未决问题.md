## 环境约束（踩过的坑）

- **Gitea 在 WSL 里**，只监听 `[::1]`；Windows 侧靠 `C:\Users\nice\gitea-tunnel.cmd`（用户态转发，每次连接重取 WSL IP）。`netsh portproxy` 在这台机器上失效，不要走那条路。会话重启后需要重新运行该脚本。
- **代理**：本地 `127.0.0.1:7890` 可用，但 Node 原生 `fetch` 默认不读环境变量，需要 `NODE_USE_ENV_PROXY=1`。
- **`pnpm run <script>` 会做依赖校验**，node_modules 与锁文件不一致时会重新安装并可能删掉手工链接；门禁脚本建议直接 `node_modules/.bin/tsx scripts/<gate>.ts`。
- **`xlsx@0.20.3`** 来自 `cdn.sheetjs.com` 绝对地址，镜像不覆盖，网络差时需要本地 tarball 兜底；改完锁文件后记得还原。
- **桌面 `dev:desktop`** 卡在 `preparePrimaryRuntime` 下载，即使加了代理也只到 57MB 就停；`launchElectron` 未执行过。
- 中文 JSON 通过 shell 直接传参会被截坏（`invalid UTF-8 within "/title"`），用文件或 Node 脚本发送。

## 当前方向（2026-11-16 澄清）

主干是**标准流程**（需求→产品定义→项目→开发→实施→验收→交付）+ **数字员工名册（常驻角色与工位）** + **史官式记录与检索**；会议降级为流程里的协商环节，进度是流程的投影。

- 暂停与常驻是三档策略（全局工作时段、角色常驻、任务级暂停），落在 `delegation` 上。

模型路由：`opencode-go` 由 `llm-pi-ai` 的 provider 配置提供（`OPENCODE_API_KEY`），不需要单独插件；真实密钥只在隔离 `DSH_HOME/.env`，不入库。目录里模型 id 是 `deepseek-v4.1-flash`（"1017" 是版本标注）。

当前可运行的本地实例（临时目录，不在仓库）：

- web 页面：`DSH_HOME=$TEMP/opencode/dsh-web-home node --import tsx/esm apps/cli/src/bin.ts web --no-open`，侧栏"会议"；数据为样例。
- 真会议脚本：`%TEMP%\opencode\meeting-real\run-real.ts`（base profile + 会议插件 + opencode-go 路由）。

## 本地怎么打开会议页面

1. 准备隔离的 `DSH_HOME` 与 web profile：`$DSH_HOME/profiles/web/package.json` 的 `dsh.profile.bundles` 加入 `@deepseek-ai/dsh-meeting-room-bundle`。
2. 让 profile 能解析到该 bundle：把 `packages/experimental/meeting-room-bundle` 链到 `$DSH_HOME/profiles/web/node_modules/@deepseek-ai/dsh-meeting-room-bundle`（Windows 用 `mklink /J`）。
3. 从源码启动，避开 `pnpm run` 的依赖校验：`DSH_HOME=<home> node --import tsx/esm apps/cli/src/bin.ts web --no-open`。
4. 浏览器打开输出的地址，关掉首次欢迎弹窗，侧栏点"会议"入口。

会看到的是假数据：六场样例会议与三份完整记录。真实会议要等页面接上 SQLite 索引。
