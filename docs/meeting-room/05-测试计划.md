# 测试计划

## V1b 验收计划与放行用例（待实现）

- 只有已确认版本可进入验收，报告绑定需求、产物和条件编号。
- 必检项全部通过且下游接收条件满足，自动策略允许推进。
- 人工策略在 Agent 通过后仍阻断下游，人工确认后放行。
- 必检项失败、无法验证或缺少证据时，保留原因并阻断自动放行。
- 返工后重新检查受影响项，需求或产物版本变化触发影响分析和重验。
- 重复结果、并发确认和重启恢复保持一次放行，员工采用可核查的版本。
- 验收团队、来源、决定与交接记录可查询，恢复任务加载相关当前背景。

## T05 Team 关联用例（初版）

- 自动放行后每个计划任务对应一个 Team 任务，负责人是被派发的员工子会话，第二项依赖第一项。
- 人工放行期间任务保持 `in_progress`，下游任务保持 `pending`；放行并续跑后先同步完成上游，再派发下游。
- Team 模式启动时关闭记录未关联并继续项目执行；Team 服务缺失同样记录未关联。
- 标记相同的既有 Team 任务被吸收，重复关联不增加任务；持久预留的执行在关联失败后可复用同一 projectId。
- 重复启动在创建 Team 任务前拒绝；关联后关闭 Team 模式使续跑以 `PROJECT_TEAM_DISABLED` 停止。
- 页面显示 Team 任务标识、状态及未关联提示；页面本身不修改 Team 任务。

## V1a 验收用例

- 项目任务通过真实子代理循环调用测试工具，检验工具执行后的实际结果。
- 第二个任务的已记录输入包含前一个任务的交接结果及自身验收条件。
- 失败或取消后不启动后续任务，结果不得进入待验收状态。
- 文件数据库关闭后重开可以查询目标、任务状态与子会话引用。
- 通过工具入口验证参数拒绝和查询行为；产品组合与录制会话测试列入发布门禁。

本页定义每个发布节点必须跑什么、怎么判定通过、证据放在哪。执行结果记入[实施记录](06-实施记录.md)。

## 分层

1. **静态门禁**：文档链接/换行/配对，类型检查，lint。改动文档或类型即适用。
2. **离线单测**：插件领域逻辑（状态机、裁决、预算），不调用真实模型。
3. **集成测试**：独立 `DSH_HOME` 数据目录 + 独立端口/应用实例，跑真实进程但不接外部模型。
4. **桌面冒烟**：Electron 安装包在干净用户目录启动，插件加载、数据持久。
5. **真实模型**：仅在需要证明 Agent 行为时使用，少量用例，结果如实记录。

## 隔离约定

- 每次测试使用新的 `DSH_HOME`（如 `%TEMP%\meeting-room-test\<用例号>`），不写用户默认 `~/.dsh`。
- Web/桌面实例使用独立端口，测试前确认端口空闲。
- 测试产物（日志、截图、导出）放临时目录，不提交；结论与关键输出抄进实施记录。

## Stage 0 测试用例

### T0-1 首轮隔离与会议根会话

- **步骤**：开启 Team 模式；用 2 个角色子代理各跑一轮首轮（spawn 语义，非 fork）；打开第二个子代理的会话日志，检查首条 `user/message`。
- **通过**：首条消息只含需求、材料与角色简报，不含第一个子代理的任何文字；两轮发言写回会议详情；重启后仍可读。
- **证据**：第二个子会话日志的首条 `user/message` 原文、`subagent/catalog` 行、会议详情截图。

### T0-2 打包与持久

- **步骤**：`pnpm run build` 后打桌面安装包；在干净目录安装启动；插入插件行后重启；创建会议并写入一条任务；关闭再启动。
- **通过**：插件随应用加载；重启后会议与任务仍在；数据目录位置可在设置中看到。
- **证据**：安装包路径、`cordis.patch.yml` 中的插件行、两次启动截图、数据目录清单。
- **替代路径**（桌面运行时下载受阻时）：用真实 `runProfile` 启动 base 或 web profile，在 profile 补丁或 `--patch` 中为插件设置文件 `databasePath` 与脚本化模型；连续启动两次、各跑一场会议，再用独立进程只读 SQLite 核对会议与轮次计数，并核对 `$DSH_HOME/sessions` 下的根/子会话日志。通过标准同上，记录中必须标注"非桌面"。

### T0-3 MCP 调用与审批

- **步骤**：`mcp-manager` 配置一个文件类 MCP 服务器；发起一次写文件调用，先拒绝、再放行。
- **通过**：`approval/asked` 与 `approval/decided` 通过 `callId` 与 `tool/call` 配对；拒绝后目标文件不存在；放行后文件存在。
- **证据**：两条审批事件的原文、`tool/call` 与 `tool/result`、文件系统检查结果。

### T0-4 页面 demo（非阻塞）

- **步骤**：主助手页、会议列表/详情用假数据渲染，复用 Conversation 渲染扩展点。
- **通过**：两页可打开，无控制台错误；失败不阻塞 N1，记入已知限制。

## 后续节点验收测试

- **N2（会议 v1）**：一场完整会议走完独立首轮 → 讨论 → 综合裁决 → 独立终审 → 发布；覆盖暂停/恢复、重启续跑、非法状态迁移被拒。
- **N3（任务与验收）**：合成任务从创建到验收；覆盖返工一次、预算超限被拦、产物指纹校验失败。
- **N4（技能/MCP/角色库）**：导入 3 个技能并分配；MCP list/call；权限拒绝可见且不执行。
- **N5（迁移与交付）**：旧库导出 → 导入 → 关键任务可继续；干净 Windows 安装启动。

## 失败与记录

- 失败即停：同一节点连续两次失败，先写问题分析再改代码。
- 每条记录至少包含：命令、预期、实际、证据、是否阻塞。
- 无法执行的测试标注"未验证"与原因（例如依赖未安装），不得写成通过。
