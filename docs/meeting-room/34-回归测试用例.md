# 回归测试用例集（2026-11-21 起维护）

本页是数字员工项目工作台的回归测试用例清单：来自历次用户反馈与走查发现，按「改动涉及面」组织。每次涉及 `client-ui-meeting-room` / `meeting-room` 的改动，先跑标注「自动」的走查脚本，再过一遍「手动」清单；新增反馈在本页追加 case 并注明来源。走查脚本位于 `.dsh-build/capture-*.cjs`（需要预览环境的带 token 地址）。

## 一、入口与信息架构

- **TC-01 侧栏双面板入口**（自动，`capture-panel-walkthrough.cjs` 场景 01/02）：侧栏同时存在「项目工作台」与「数字员工与团队」；点击各自渲染独立面板，互不混装。
- **TC-02 项目切换条**（自动，`capture-project-switcher.cjs` 场景 58/59）：chips 显示「状态点 + 状态文字 + 目标」；切换后看板、摘要条、右栏配置全部跟随选中项目；单项目时不显示切换条。
- **TC-03 层级入口**（手动，层级入口落地后补充自动化）：新建项目后可从项目列表打开该项目面板；工作台默认展示项目列表而非全部任务平铺（参考图：新建项目后再打开项目面板）。

## 二、工作台面板

- **TC-04 看板/列表视图**（自动，`capture-board-list.cjs` 14 断言）：切换条两态；列表分组折叠与恢复；两视图同一任务集合；各项目视图状态独立。
- **TC-05 看板容器与区分**（手动 + 截图对照 `58/59`）：看板区块有容器边界；多项目时页面长度不随项目数增长。
- **TC-06 任务详情**（自动，走查场景 08）：卡片「验收条件」打开详情，收起关闭。
- **TC-07 全屏看板**（自动，走查场景 07）：全屏打开、退出关闭。
- **TC-08 产物文件打开**（自动，`capture-file-open.cjs` 落地后补充）：看板卡产物 chip 与资产表行**左键打开内容查看器**（Modal 展示全文 + 观察哈希），查看器内提供下载文件与复制路径按钮；右键不再绑定基座文件菜单（会话外基座动作会静默失败，已移除）；计划文档 chip 同款。
- **TC-30 产物白名单**（自动，`preset-roster.spec.ts` 白名单用例 + 手动）：仅本会话计划文档、计划内约定产物路径（按计划工程目录解析）、验收报告已核对产物可读取；未产出文件给出基础层明确提示而非静默失败。
- **TC-09 资产表**（自动，`capture-assets.cjs` 14 断言）：计划文档/约定产物/已核对产物聚合与实际产物一一对应；计数徽标一致；空态文案。
- **TC-10 计划卡生命周期**（自动，走查场景 11 + 手动）：未启动计划显示确认/运行（primary），已启动仅显示修改计划（outline）；不误触真实确认/运行。
- **TC-11 背景材料两级收起**（手动 + 截图对照）：外层「背景材料与来源 · N」折叠；展开后每条来源独立折叠，不再平铺长文。
- **TC-12 查看计划锚点**（自动，`capture-anchor-flash.cjs` 场景 69）：滚动落点避开固定页头（scroll-margin）；目标卡边框闪烁提示约 1.8 秒；reduced-motion 下为静态描边。
- **TC-13 右栏项目配置**（自动，走查场景 10 + 截图对照 `67`）：仅项目范围条目（团队名 + 成员数 + 打开花名册面板按钮、计划版本、资产计数锚点）；无模型组合冗余；收起/展开；资产锚点带闪烁。
- **TC-14 自动同步**（自动，`capture-live-sync.cjs` 落地后补充）：执行在途时，工作台不手动刷新也会随推送流更新（计划草稿、检查点）。
- **TC-15 推送流断线重连**（手动，服务重启场景）：服务重启后面板恢复订阅并自动补齐数据，不出现永久静默。

## 三、数字员工与团队面板

- **TC-16 员工编辑器**（自动，走查场景 03）：名称/说明/职责/连接/模型/推理力度/备用路由/预设全字段；取消保留数据；保存往返新字段。
- **TC-17 团队编辑器**（自动，走查场景 04）：名称/团队说明/协作指令/负责人（限成员）/允许指派开关/成员复选；保存往返。
- **TC-18 团队卡展示**（自动，走查场景 05 + `capture-roster-fields.cjs` 7 断言）：展开/收起成员；负责人 chip；指派停用 chip；模型链行保留。
- **TC-19 团队预置**（自动，`capture-preset-teams.cjs` 落地后补充）：插件首次启用自动预置参考团队与员工；手动创建的团队与员工不受影响、不被覆盖。

## 四、新建项目

- **TC-20 弹窗可用性**（自动，走查场景 06）：表单完整落在视口内且可滚动；名称必填门（无名称确认禁用）；取消不发起会话。
- **TC-21 提示词组合**（自动 + 手动）：发起后新会话草稿包含「项目名称 + 项目指令 + preparePrompt」组合文本；确认发送后才启动主助手。

## 五、端到端全流程

- **TC-22 全流程 0→1**（自动脚本链，`capture-e2e2-*` 系列 + 手动确认）：提出需求 → 主助手存计划草稿（拆解符合专业流程：方案/实现/测试分离、验收标准可判定）→ 工作台确认 → 执行 → 子代理产出 → 验收 → 放行 → 成果落地（产物在磁盘可核实）。
- **TC-23 受阻恢复链路**（手动 + 截图对照 `47/48/51/52/54`）：执行受阻时看板/摘要/子会话三层亮出原因；交互提问可用；路由修复后自愈重试另存新版本。
- **TC-24 产物实测**（手动/无头浏览器）：项目完成后对交付物本体做独立验证（如游戏可玩性），不依赖验收报告自述。
- **TC-25 团队联动提示**（手动）：团队模式未启用时看板显示停用提示且无 Team 任务镜像；启用后镜像恢复——文案与机制解释见 33 号。
- **TC-31 项目列表滚动与置顶**（自动，`capture-project-switcher.cjs` 场景 76）：列表限高内部滚动；执行中项目优先排序；置顶/取消置顶持久（localStorage）。
- **TC-32 配置前移**（自动，走查场景 77）：页头动作顺序「返回项目列表 / 刷新进度 / 提出需求 / 团队配置」；摘要条仅保留查看计划与向主助手提出调整。
- **TC-33 花名册排序**（手动 + 截图对照 `80`）：已保存团队在前、数字员工列表在后（带小节标题）。
- **TC-34 计划卡 meta 格子化**（手动 + 截图对照）：版本/团队/确认状态/查看计划/执行状态收纳进带底色边框的子块。
- **TC-35 覆盖率门槛**（自动）：`meeting-room` 与 `client-ui-meeting-room` 两包行覆盖不低于 95%（现状与补齐计划见下）。

## 执行约定
