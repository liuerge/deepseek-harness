### 2026-11-15 · 依赖安装失败与重试

- 计划：`pnpm install --frozen-lockfile` 安装工作区依赖，解除门禁阻塞。
- 问题：安装以 `TypeError: fetch failed` 失败（pnpm 11.28.5，`@pnpm/exe` 内部栈），未指明具体包。
- 测试：
  - 命令：`curl -m 15 https://registry.npmjs.org/pnpm`、`https://registry.npmmirror.com/pnpm`。
  - 实际：两者均返回 200；`pnpm config get registry` 为官方源，无 `.npmrc` 覆盖，仅有 `NO_PROXY=127.0.0.1,localhost,::1`。
  - 判断：瞬时网络失败，而非源不可达。
- 处理：重试并加 `--fetch-retries=5 --network-concurrency=4`，降低并发与重试放大。
- 结论：等待重试结果。
- 未验证：全部依赖是否可下载；若再次失败，需抓取具体包的 URL 与错误码再判断。
- 追加：首轮重试跑到 2.3G（`.pnpm` 内 1416 个包）仍未结束，且 `electron@44.7.0` 的 `dist/` 为空——二进制走 GitHub 下载，不受 `--registry` 影响。改为带镜像重跑：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright`、`--registry=https://registry.npmmirror.com`，并发提到 8。已下载的包在 pnpm store 中，重跑不重复下载。
- 结果：镜像重跑完成了 1429 个包的复用与 1436 个链接，只剩一个包失败：`xlsx@0.20.3` 来自 `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`，`ERR_PNPM_FETCH_TIMEOUT`（60 秒无数据）。这是 lockfile 里的绝对 URL，不经 npm 源，镜像无法加速。
- 诊断：`curl -I` 该 URL 返回 200、`Content-Length: 2409319`，说明可达，只是 Node 侧首次请求慢或超时。
- 处理：改为 `--fetch-timeout=180000` 重跑，其余包均已缓存。
- 结果：仍然超时，且重试后报 `fetch failed`；同一 URL 用 `node -e "fetch(...)"` 直接请求返回 `200` 与 `2409319` 字节，确认不是网络不可达。
- 追加处理：降到 `--network-concurrency=1 --fetch-timeout=300000 --fetch-retries=10` 再试，避免同主机并发与短超时叠加。
- 追加诊断：直接 `curl` 下载同一 URL 在 132393/2409319 字节处超时，说明 CDN 对该网络不稳定，pnpm 的超时并非配置问题。已用 `curl -C -` 断点续传 + `--retry 30 --retry-all-errors` 后台拉取，下载完成后按 lockfile 的 `sha512-oLDq3jw7…` 校验。
- 已知依赖方：`xlsx` 仅被 `packages/client/ui-sidebar-documentpreview` 使用，不影响文档门禁。
- 兜底方案（需还原）：临时把该依赖改成本地 tarball 安装，装完用 `git checkout -- package.json pnpm-lock.yaml` 还原，避免把环境特例提交进仓库。
- 结论：待续传结果。

### 2026-11-15 · Stage 0 前置事实（MCP、审批、桌面插件、页面）

- 计划：确认 MCP 注册与审批链路、打包后如何加载自定义插件、客户端页面扩展点。
- 发现（含代码位置）：
