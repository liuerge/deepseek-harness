# 项目治理与验收基线

本参考记录数字员工项目工作台的已确认治理要求、公开资料依据和待实现能力。确认日期为 2026-11-16。需求、计划、验收与背景资料在仓库内持久保存，运行中的项目还需将相应版本交付给执行和验收员工。

## 已确认的产品要求

用户在规划阶段确认交付标准、验收条件、下游依赖节点的输入要求，以及各节点的放行方式。验收 Agent 按已确认内容组队执行检查。节点支持 Agent 验收通过后自动放行，也支持 Agent 验收通过后由用户再次验收。用户可在执行期间修正方向，变更应带版本并识别受影响的任务、产物和历史验收。

前期确认形成当前执行版本。项目推进中出现新事实、技术限制或范围调整时，通过变更控制更新版本，保留先前版本和确认记录。

## 项目经理与验收团队职责

| 角色 | 职责 | 必须留下的记录 |
|---|---|---|
| 用户或项目负责人 | 确认目标、范围、预算、验收授权与关键变更，处理需要人工确认的节点 | 确认的版本、权限范围、决策与理由 |
| 主助手或项目经理 Agent | 澄清需求、拆解任务、协调资源与依赖、监控偏差、安排验收及返工 | 计划、负责人、阻塞、依赖、风险与决策请求 |
| 执行员工 | 按任务及当前版本操作工具、产出成果、提供检查证据 | 工具日志、产物版本、自检与交接 |
| 验收负责人 | 为每项条件安排检查角色，汇总必检项及未决问题 | 逐项检查结论、证据、版本和团队汇总 |
| 专项验收员工 | 根据任务需要执行功能、技术、产品等检查 | 实际操作与结果、失败或无法验证的原因 |
| 下游接收角色 | 核查上游输出是否满足后续节点输入需求 | 接收条件、版本、兼容性及缺失项 |
| 史官角色 | 整理已确认事实、决定、变更、来源和交接材料 | 可追溯的项目知识及待解决问题 |

验收团队按检查需求组建，团队成员数量由实际工作决定。关键产物由不同于产出者的角色复核。项目经理依据状态和证据推进，验收结论由对应的检查和放行授权产生。

## 启动前确认的验收计划

每项任务或节点应保存以下内容。

- 需求编号、需求版本、目标、约束和范围。
- 交付物清单、格式、存放位置及版本识别方式。
- 每条验收条件的编号、检查方法、通过阈值和证据要求。
- 验收负责人、专项角色和各自负责的条件。
- 下游节点、依赖的交付物及下游接收标准。
- Agent 自动放行或 Agent 验收后人工确认的节点策略。
- 失败返工负责人、重验范围、重试预算及需要用户决策的条件。
- 计划确认人、确认时间、授权范围及确认版本。

验收报告逐项引用条件编号、需求版本、产物版本和检查证据，结论包括通过、不通过和无法验证。无法验证的必检项需要补充证据或交由有权决定的人员处理，处理结论必须留存。

## 节点推进与返工

执行产出后进入 Agent 验收。任何必检项失败时，记录缺陷并安排返工；修复后按影响范围重新验收。所有必检项通过且下游接收要求满足时，根据已确认策略自动放行或进入待人工确认。需要人工确认的节点由用户确认后放行。

下游任务只消费已放行的产物版本。产物在验收后变化时，应重新计算受影响的检查和依赖。验收文字或单个 VERIFIED 标记需要与实际证据、全部必检项及放行规则共同核查。

## 变更控制与背景保留

变更保存提出者、时间、理由、涉及的需求和产物、对成本与进度的影响、需要重验的范围、确认人和生效版本。待决变更交由确认计划中指定的决策者处理。已经运行的任务应明确当前采用的版本，收到新版本后报告采用情况及受影响工作。

项目资料按用途保留，彼此通过编号和引用连接。

| 资料 | 保存内容 | 更新时机 |
|---|---|---|
| 需求与验收基线 | 当前确认内容及先前版本 | 用户确认或变更生效时 |
| 参考资料索引 | 标题、机构、链接、版本、查阅日期、摘要及采用理由 | 调研产生新依据或原资料变更时 |
| 决策记录 | 决策、理由、适用范围、确认人及被替代关系 | 决策确认时 |
| 执行与验收事实 | 会话、工具动作、产物、检查结果及放行记录 | 操作发生并提交时 |
| 交接摘要 | 当前目标、执行版本、已完成工作、阻塞和下一步 | 任务交接、暂停、恢复或上下文压缩前 |

史官从执行事实整理摘要，关键结论带回原始记录引用。员工启动、恢复、换人及上下文压缩后读取相关需求、验收计划、决定和交接材料。知识索引可重建，已确认版本和原始执行记录应可查询。

## 暂停与恢复语义

用户于 2026-11-16 确认以独立 SuperAgent 原型的 Pause processing 为准。暂停停止新派发、新研判、研判超时处理、自动输入递送和对外回复。已进入启动流程的执行等待恢复；正在运行的员工回合继续，不强制中断。来源继续记录输入，排队输入持久保留，暂停期间不自动递送或唤醒新执行。进行中的研判期限按暂停时长顺延。

界面分别呈现调度已暂停、仍在执行、排队及待递送状态，不能将调度暂停显示为所有员工已停止。现有直接停止单个执行的能力保留独立入口，不作为暂停的隐含动作。恢复时校验当前授权、确认版本及待处理结果，再继续派发和递送。该语义是已确认要求，项目级实现仍见任务状态。

## 当前实现与后续实施

当前已实现有序项目执行、自由文本验收条件、员工交接、检查点持久保存、员工名册及真实项目页面。计划草稿保留版本、来源材料和员工配置，工作台可确认具体版本，按计划执行核查确认状态并防止重复启动。真实模型已验证文件交付、独立员工检查和授权背景原文传递，事实见实施记录。

串行 UTF-8 文件节点已实现结构化验收、独立组队、逐项结果、自动或人工放行及检查点续跑。计划可预先授权有界返工，失败后保留报告并阻断下游，主助手在原范围内安排修复并重新独立验收。返工次数包括失败及中断，旧报告与新报告分别保留。启用 Team 时，计划任务在派发前建立共享任务关联并按顺序依赖；自动放行完成任务，人工放行在续跑时同步，未放行节点不解除下游依赖。并行依赖调度、Team 任务人工改派后的核对、需求变更后的影响分析、一般中断恢复与运行时知识检索仍待实现。开发顺序及验收用例分别见迭代计划和测试计划。
