# 目标与产品定位

## 一句话目标

把"会议室"从讨论工具升级为**可验收的数字员工团队**：用户只提供方向，主助手负责拆解、开会、调度、交付，用户只做关键决策和最终验收。

## 用户痛点（来自现有产品使用）

- 现有底座在工具、技能、桌面体验上偏弱：Agent 能讨论，但"像真实员工一样找文件、执行工具、用技能"的能力不够。
- 多 Agent 会议有价值，但过程不够透明：谁在做什么、中间结果是什么、最终产出在哪里，需要更直观。
- 用户不想自己配置工作流/技能；希望开箱即用，同时保留深度定制空间。

## 产品定位

**一个本地优先、桌面可用的多 Agent 工作台**：
- 主助手（SuperAgent）是唯一对接人：理解目标、拆解任务、调度角色 Agent、汇总交付。
- 会议是核心协作方式：角色 Agent 按治理流程讨论（独立首轮、争议裁决、独立终审），产出方案。
- 任务与验收闭环：执行、审核、验收、返工、产物登记、预算与调用上限。
- 能力可扩展：技能（SKILL.md）、MCP/CLI、自定义 Agent；能力 Agent（文件/搜索/浏览器/系统）给角色 Agent 使用。
- 过程透明 + 关键动作审批：看得见、拦得住。
- 桌面应用（Windows），本地数据、本地模型/网关，不依赖云。

## 参考产品与取舍

### Marvis（腾讯）的设计点
- 一个主 Agent 总指挥：一句话 → 拆解 → 调度 → 汇总，用户不配置工作流。
- 出厂预置能力 Agent：File / Computer / App / Browser / Search，开箱即用。
- 过程透明：当前步骤、哪个 Agent、中间结果、最终产出；日志可追溯。
- L2 硬审批：关键动作必须用户确认。
- 可扩展但不强制：自定义 MCP/CLI、导入 Skill、自定义 API。
- **借鉴产品原则，不复制其 UI 资产或文案。**

### DSH 的能力（底座）
- 插件化（Cordis），Web + Electron 桌面，会话/Agent 循环、工具、MCP、技能、模型适配器。
- 适合承载"主助手 + 会话 + 工具执行"；多 Agent 会议的编排需要我们在插件里实现。
- 开发者预览期：固定版本、加适配层，不追每个上游提交。

### 现有会议室（业务规则来源）
- 已有：项目/员工/团队、讨论治理（独立首轮、异议台账、独立终审）、任务生命周期、验收、预算、主助手、员工/团队评价、技能 v1/v2。
- 这些业务规则保留，作为新产品的领域逻辑；UI 与运行时迁到 DSH。

## 核心差异化（不要丢）

1. 会议治理：不是"多 Agent 随便聊"，而是有独立首轮、争议逐项裁决、不同作者终审、发布门槛。
2. 任务与验收：真实产物、检查证据、人工最终确认；不是"模型说完成"。
3. 角色与能力分离：角色 Agent（产品/架构/开发/测试/验收/运维/数据）负责决策与交付；能力 Agent（文件/搜索/浏览器/系统）作为工具。
4. 主助手统一入口：用户只和主助手对话；会议与任务都是它调度的协作单元。
5. 本地优先与审计：数据、日志、审批都在本机。

## 非目标（本阶段）

- 不做云端多租户、团队协作服务器。
- 不开放无审批的原生系统工具。
- 不复制 Marvis/DSH 的源码 UI 资产；只借鉴信息架构与交互原则。
- 不追求一次迁移全部历史数据；先新库、后导入。
