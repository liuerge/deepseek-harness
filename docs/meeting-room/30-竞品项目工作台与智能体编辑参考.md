## 竞品的信息架构

九张图合起来是一条完整链路：项目列表 → 新建项目（一次性配好指令、连接器、专家、技能）→ 项目工作台（计划的多视图 + 资产文件区 + 右侧常驻配置栏）→ 团队（负责人 + 成员 + 协作指令）→ 数字员工（执行配置 + 工作指令 + 可选能力 + 工具权限）。竞品把「项目」做成自带对话输入框的工作台：一级 tab 是动态 / 计划 / 任务 / 资产，主区随 tab 切换，右侧配置栏常驻，底部是对话框。

竞品的工作台配置项与新建弹窗附件行一一对应：弹窗里选过什么，工作台右栏就列什么，右栏可随时增删。两处是同一份配置的「创建时选」与「项目内改」两个入口。

## 与我们的字段对照

我们侧的对应物是 `packages/experimental/meeting-room` 的 `Employee` 与 `ProjectTeam`（[types.ts](../../packages/experimental/meeting-room/src/types.ts)）。

### 团队

| 竞品字段 | 我们的现状 | 缺口 |
|---|---|---|
| 名称（7/80） | `ProjectTeam.name` | 无 |
| 说明（45/500） | 无 | 缺字段，且说明会出现在团队选择处 |
| 协作指令（团队分工、调用优先级、验收责任，长文本） | 无；分工目前写在每名员工的 `responsibility` 里 | 缺字段，价值最高：它把「谁先谁后、谁验收」从逐人职责里提到团队层 |
| 成员：负责人 + 至多四名额外成员 | `memberIds`，成员无角色区分 | 缺「负责人」语义：负责人直接领任务并协调成员 |
| 运行：允许指派开关 | 无 | 缺字段 |
| 头像（随机配色与花纹） | 无 | 可用 `ui-primitives` 固定调色板加首字母替代，不引入图片资产 |

### 数字员工

| 竞品字段 | 我们的现状 | 缺口 |
|---|---|---|
| 名称、说明 | `Employee.name`、`Employee.responsibility` | 说明与工作指令在竞品是两段，我们只有 `responsibility`，语义混着两者 |
| 模型（跟随定义） | `provider` + `model` + `reasoningEffort` + `fallbacks` | 我们的模型路由比竞品更细，无缺口（[模型路由加固决策记录](27-数字员工模型路由加固决策记录.md)、[多员工差异化模型路由实测](28-多员工差异化模型路由实测.md)） |
| 默认权限（自动审批） | 无员工级权限字段 | 缺字段 |
| 生效范围（主智能体 / Agent Team） | 由 `preset` 隐式表达 | 缺显式字段：这个员工在哪些宿主里可用 |
| 工作指令（长文本） | `Employee.responsibility` | 同「说明」一行 |
| 可选能力（Skills / MCP Server 引用 / Plugins 逐项勾选） | `preset` 是整包粒度 | 缺逐项选择；DSH 侧技能、MCP、插件能力已存在（`packages/skill`、`packages/mcp`、插件注册） |
| 工具权限允许 / 禁止清单 | 权限模型在 `packages/client/ui-permission-presets` 与 preset 层，不在员工层 | 缺员工级工具权限 |
| 执行位置 | 无对应字段 | 缺字段 |

## 采纳边界

**采纳（不动持久化结构）**：项目工作台右侧常驻「项目配置」栏、资产文件表格化、计划区「看板 / 列表」视图切换、团队与员工的层级展示（团队卡片展开成员、头像）、新建项目弹窗的字段与附件行形态。

**不采纳**：竞品的一级 tab（动态 / 计划 / 任务 / 资产）与底部内嵌对话框。DSH 的会话是独立页面、项目工作台是主区页面，照搬会与 `ui-conversation`、会话级 `ui-plan` 的边界冲突，也与 [项目工作台设计参考](20-项目工作台设计参考.md) 中「是否引入分区导航」这个未决问题直接相撞；折中做法是在工作台内部做「看板 / 列表」视图切换条，资产作为独立分区。

**不采纳**：竞品的甘特与日历视图。它们的行模型是排期，与我们按执行状态分列的语义不匹配。

**不跟随**：竞品的列语义是待开始 / 进行中 / 已暂停 / 已完成；我们已定「列语义取执行状态」（待开始 / 进行中 / 待验收 / 已通过 / 受阻），只借鉴「一行一状态 + 负责人头像 + 可折叠分组」的呈现。

**单独决策**：竞品配置栏里的定时任务在我们的 `packages/schedule` 是会话级定时任务，挂到项目上是新增语义，需要单独评估。

## 字段缺口带来的流程影响

团队与数字员工的上述缺口落在 `ProjectTeam` 与 `Employee` 两个持久化类型上，属于持久化类型变更：需要走 [持久化变更记录](../persistence-changes/README.md)、[类型变更确认](../cookbook/reviewing-persistence-type-changes.md)、Agent Note 与升级指南，不能与界面改动混在同一次提交里。
