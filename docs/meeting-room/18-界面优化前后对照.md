# 界面优化前后对照

本页是 [界面走查与优化建议](17-界面走查与优化建议.md) 中 P0+P1 六条建议的前后截屏对照与验收记录。before 与 after 各 6 张，逐屏并排归档；验收结果按实际回验填写。

## 范围

本轮实现 P0+P1 六条：P0-1 状态 chip、P0-2 执行区去重、P0-3 弹窗动作重排、P1-4 内容列限宽、P1-5 路径与哈希组件化、P1-7 模型显示去重。P1-6 用户提示词去技术化暂缓（model-visible prompt，改动会触发录制会话快照回放），P2 本轮不做。

## 捕获条件

| 条件 | 取值 |
|---|---|
| 视口 | 1780 × 1210 CSS px |
| 主题 | 浅色 |
| 语言 | 中文 |
| 字号 | 14px |
| dpr | 1 |
| 数据 | 五子棋复杂场景的真实成果数据（同一 `DSH_HOME`） |
| 预览实例 | 同一 WSL 预览（3080、`base + web-app + meeting-room-bundle`），after 前重启以加载新产物 |
| 场景重放 | before 与 after 用相同的滚动锚点、折叠/展开状态与交互路径重放，仅客户端产物不同 |

before 由 OpenCode 桌面应用内嵌 Chromium 拍摄；after 阶段桌面窗口不可见，改用同系统的 headless Chromium（Playwright 1.61）按同一视口、dpr、主题、语言、数据与场景锚点拍摄。两者字体渲染可能有细微差异，逐屏对照以内容关系与布局为准。场景重放脚本见 `.dsh-build/ui-review-scenes.md`（本地取证文件，不入库）。

## 逐项改动与验收

| 建议 | 改动前现象 | 改动后预期 | 验收结果 |
|---|---|---|---|
| P0-1 状态 chip | 「已确认」「已完成」「Agent 检查通过」等为纯文本或普通加粗，无状态点或语义色 | 统一为状态点 + 文案、复用 `StateDot` 语义 token、不铺色块 | 已回验（01、03、04）：计划确认、执行状态、任务状态、报告与 AC 结论均为状态点 + 文案；`statusTone` 覆盖 done/warning/ongoing/error/idle 五档。本轮数据只有成功态，失败与待处理态的截图未补。 |
| P0-2 执行区去重 | 目标句与任务指令在「项目计划与确认」和「执行记录」各出现一次，需跨块对照 | 执行记录只显示「依据计划版本 N」摘要并带锚点，指令与验收原文仅留在计划块 | 已回验（03）：执行区出现「依据计划版本 1 · 查看计划」，`查看计划` 为指向 `plan-<id>` 的锚点，任务指令与验收原文已从执行区删除。 |
| P0-3 弹窗动作重排 | 380px 内三个文字按钮折成两行、末项孤立，主操作层级不清 | 底部只留「清除团队选择」与带 `aria-label` 的刷新图标，「配置员工与团队」移出底部，380px 不折行 | 已回验（06）：底部为「清除团队选择」+ 刷新图标按钮，单行不折行；配置按钮移到弹窗内容区（团队列表上方），仍可调用；主操作「使用 五子棋交付团队」留在列表内。 |
| P1-4 内容列限宽 | 超宽视口下正文列约 1500px，长句单行超过 140 字符 | 主内容列约 1100px 居中 | 已回验（01、02、03、04）：`.page` 计算样式 `max-width: 1100px`，内容居中，英文长句在约 90 字符处折行。 |
| P1-5 路径与哈希组件化 | 绝对路径与 64 位哈希直出，不可点击、不可复制 | 文件 chip 显示 basename 与悬停全量路径，哈希显示前 8 位 | 已回验（01、04）：计划文档、证据路径、产物版本均显示 basename，完整路径与完整哈希放在 `title`，哈希截断为前 8 位；`FileChip` 通过 `PropsRuntime<'main'>` 的 `useContextMenu` 绑定 file target 右键菜单（右键动作本身未在本轮截图里触发）。 |
| P1-7 模型显示去重 | name 与 id 重复显示，成员行模型 id 在连字符处折行 | name 与 id 相同时只显示一次，成员行模型 id 不折行加省略号 | 已回验（05、06）：连接下拉只显示「opencode-go」；成员行 `deepseek-v4.1-…` 单行尾端省略，未再折成两行。 |
