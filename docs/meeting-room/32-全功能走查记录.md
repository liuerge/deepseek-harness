# 全功能走查记录：入口拆分、弹窗修复与提出需求到成果落地（2026-11-21）

本页记录三项用户反馈的修复（数字员工入口不明确、新建项目弹窗显示不全、产品入口与交互未随界面调整更新），随后对两个面板的全部可点击面逐项走查（16 项断言），最后用真实模型走通「提出需求 → 计划草稿 → 确认 → 执行 → 受阻 → 路由修复 → 重执行 → 验收放行 → 成果落地」全流程。截图存 `ui-review-20261121/`。

## 用户反馈与修复

- **花名册入口不明确**：修复前花名册是工作台长页面的尾部区块，入口不明确。修复：注册第二个侧栏面板 `project-roster`（「数字员工与团队」，order 20），`RosterEditor` 整体迁入独立面板（新组件 `RosterPanel`），工作台面板摘除花名册区块；`configureEmployee`/`configureTeam` 两个无人消费的注入键一并移除。截图 `01-sidebar-panels.jpeg`、`02-roster-panel.jpeg`。
- **新建项目弹窗显示不全**：修复前弹窗无高度约束，表单超高被视口裁剪。修复：弹窗固定宽高（`min(480px, calc(100vw - 32px))` 乘 `min(600px, calc(100vh - 48px))`）加内容区滚动。截图 `06-new-project-dialog.jpeg`。
- **顺带发现**：`MeetingListPage`/`MeetingDetailPage`/`MeetingRoomPanel` 三个组件无任何注册入口（「会议 I2」时代的遗留），会议功能在当前产品形态下不可达。重建需要重接 meeting-store 装配，属产品线决策，本页只记录不擅自恢复。

## E2E 全流程（真实模型 DeepSeek-V4.1-Flash）

- **发起**：弹窗填「裁纸刀走查项目」（名称 + 指令）→ 发起项目 → 新会话自动命名「裁纸刀走查项目计划」，组合提示词（项目名称、项目指令、`plan.preparePrompt`）完整进入草稿（`40-e2e-发起需求.jpeg`、`41-e2e-需求已发送.jpeg`）；选择模型 DeepSeek-V4.1-Flash 后发送。
- **计划草稿**：主助手读取 `employee_list`、编辑 `walkthrough-plan.md`（T1 + C1/C2 验收 + 自动放行），工作台出现「待确认」计划卡（`probe-session.jpeg`）。
- **确认与执行**：工作台点「确认此版本」→「按此版本执行」→ 主会话预填 `project_execute` 草稿 → 发送（`42-e2e-计划确认.jpeg`、`43-e2e-计划运行.jpeg`）。
- **受阻**：编写员工派发因 `opencode-go` 连接额度耗尽（QUOTA 429）受阻——看板受阻列、摘要「执行失败」、子会话「本轮运行失败 当前请求的额度已用尽」逐层亮出，失败路径的产品行为验证通过（`47-e2e-执行观察.jpeg`、`48-e2e-受阻会话.jpeg`）。
- **交互与恢复**：主助手交互提问三选一（`51-e2e-交互提问.jpeg`），选择推荐项提交（`52-e2e-选项已提交.jpeg`）；其 `employee_save` 先撞上 `ROSTER_STALE`（此前已手动在花名册改路由），随后重读花名册自愈重试，另存计划 revision 2（`54-e2e-助手自愈.jpeg`）。
- **重执行**：工作台确认版本 2（`53-e2e-版本2确认.jpeg`）→ 发送执行指令（`55-e2e-版本2执行指令.jpeg`）；编写员工经 `deepseek-official / deepseek-flash` 产出 hello.txt，验收员工独立复核 C1/C2 通过后自动放行。
- **成果落地**：看板「已通过 1」、摘要「版本 2 · 已完成」、资产 3 项（计划文档、约定产物、已核对产物 hello.txt 带哈希）（`46-e2e-成果落地.jpeg`）；磁盘核实 hello.txt 内容恰为 `hello walkthrough`（18 字节，`.dsh-build/complex-scenario/project/hello.txt`）。

## 用户反馈批次（2026-11-21）

### 入口与层级

- **层级入口**（用户反馈 + 参考图「新建项目后再打开项目面板」）：工作台默认改为**项目列表**——「我的项目」卡片（状态 chip + 团队 + 版本）加「从模版创建」网格（5 个专业模板：产品需求全流程、市场调研与竞品分析、团队知识库、项目交付、Bug 跟踪/测试验收，点击预填新建弹窗）；点击项目卡进入该项目的工作台（看板 + 资产 + 计划 + 右栏），页头「返回项目列表」。多项目不再平铺（截图 `70`、`71`）。

### 可用性

- **弹窗显示不全**：弹窗固定宽高加内容滚动（截图 `06`）。
- **按钮可供性**：19 处 ghost 按钮按变体约束统一为 outline/primary（33 号），摘要条「向主助手提出调整」等静止态即可辨识（截图 `56`、`57`）。
- **查看计划锚点不聚焦**：锚点滚动加 `scroll-margin-top`（避开固定页头）+ 目标卡边框闪烁 1.8 秒（reduced-motion 为静态描边）；右栏资产锚点同款（实拍 `69`）。
- **背景材料平铺**：计划卡背景来源改两级收起——外层「背景材料与来源 · N」，每条来源独立折叠（截图 `73`）。
- **产物与资产文件打开**：`FileChip` 左键唤起既有文件菜单（在侧边栏打开 / 浮窗打开 / 使用默认应用打开 / 下载 / 复制路径 / 添加到对话），看板产物 chip 与资产表行均可点击（截图 `74`）。

### 同步

- **执行中工作台不同步**（用户反馈）：根因为推送流断线后客户端不重连——服务端 `follow` 流本身覆盖计划保存、确认、检查点、状态迁移四类写操作；修复为断线指数退避重连（2s → 30s 封顶），服务重启或网络抖动后面板自愈，不再静默停更。

## 发现与遗留

- `opencode-go` 连接额度耗尽是环境问题（worker 会话 QUOTA 429 证据），不是产品缺陷；「受阻 → 交互提问 → 路由修复 → revision 2 重执行」的恢复链路本身就是一次真实产品验证。
- 会话草稿提示词不跨页面刷新持久（composer 草稿为会话内存态）：「按此版本执行」等准备型指令必须在同一次会话流内发送。当前行为与「准备不自动执行」的定位一致，草稿持久化值得产品侧评估。
- 会议面板入口缺失为待办的产品决策（见上），建议单独一轮处理。
- E2E 的模型用量：主会话两轮 818K tok（缓存命中 96%）。
