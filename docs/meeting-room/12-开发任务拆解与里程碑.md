# 开发任务拆解与里程碑

本参考把数字员工项目工作台目标拆为实施任务、依赖和可观察的验收结果。当前验收和背景保留规则见[项目治理与验收基线](11-项目治理与验收基线.md)。本计划按里程碑安排，日期在核心执行与验收机制实测后估算。

## 与本工程产品目标的对应

产品目标是基于 DSH 的本地数字员工团队工作台。用户向主助手下发需求，主助手根据可复用员工与团队、角色模型、技能及工具权限组织执行，在需要协商时安排会议，保存背景与决定，按授权验收交付。用户能观察工位和成果、修正方向、暂停或让团队持续运行。项目流程与验收规则服务于这条用户路径。

当前开发落在自有 Host 插件、Client 页面和 bundle 中，延续已确认的接入形态。下面列出原产品内容、已有基础及本轮计划，便于逐项检查范围。

| 原产品内容 | 工程已有基础或接入位置 | 对应任务与需要补齐的内容 |
|---|---|---|
| 主助手接需求并组织工作 | DSH 根会话、子代理；自有 project_execute 工具 | T01–T05、T20，把自然语言需求转成可确认计划，按名册组队并执行 |
| 数字员工、团队与工位 | DSH agent presets、subagents、Team；自有 Client 页面 | T19、T07，保存员工身份、模型、职责和团队模板，显示实际任务与产出 |
| 技能、MCP、文件、搜索、浏览器与命令能力 | packages/skill、packages/mcp 及已有工具提供者 | T21、T06，建立员工与任务能力绑定，验证真实工具使用和权限提示 |
| 会议协商与治理 | 自有 meeting-room Host，会议 Client 页面 | T22，按流程需要安排会议，将方案、异议和决定关联到需求及任务 |
| 史官记录和知识复用 | Session 日志、自有项目检查点、仓库规划资料 | T03、T12，记录有来源的事实与决定，员工工作前检索相关背景 |

| 暂停、多项目与全天运行 | DSH goal、schedule、subagent 控制和工作区能力 | T14–T17，增加项目级联动、隔离、预算及恢复策略 |

| 原会议室资料与员工履历 | 规划中的历史业务规则，原工程数据需另行盘点 | T24，列清数据与业务规则迁入范围，保留引用与来源 |

上述 DSH 能力按已有扩展点复用。员工业务身份、项目阶段、验收和知识管理由自有插件负责。近期优先完成共享任务与 Team 的关联及状态整合，再扩展背景检索、纠偏、暂停和新页面；[技术方案](03-技术方案与阶段计划.md#既有能力复用与状态归属)定义事实归属及复用限制。

员工身份与业务履历持久保留，每次执行可以启动新的子会话。运行时是否常驻由工作策略决定，工位显示其实际运行状态。已实现持久员工名册和团队模板，支持员工职责、模型与可选 DSH 预设引用，执行时保存所选配置版本。逐技能/MCP 编辑、员工活动工位和计划确认版本仍待实现。

## 当前起点

已有项目执行与记录查询工具、有序员工执行、前序交接材料和真实项目页面。确认计划绑定验收标准，独立员工检查后按自动或人工策略放行；预先授权的失败验收可关联返工并独立重验。页面采用手动刷新，不把任务产出等同于验收通过。

持久依赖图调度、运行时背景检索、项目级暂停恢复、工作时段及多项目隔离仍需开发。现有串行文件验收及返工已用于真实模型合成验证，生产验收仍需逐项证据、对应工具能力和明确授权。

## 交付阶段

| 阶段 | 用户能完成的操作 | 完成判据 |
|---|---|---|
| 第一阶段，配置团队并确认项目计划 | 主助手使用员工与团队模板理解需求，生成任务和验收计划 | 员工配置与计划重启可读；启动前按授权确认版本 |
| 第二阶段，观察真实执行 | 启动项目，看到任务、工具、产物和阻塞 | 任务由持久状态推进；显示员工工位和工具能力；失败及未知结果可见 |
| 第三阶段，验收与返工 | 让验收团队检查，按节点自动或人工放行 | 两种策略和返工闭环均通过真实产品入口验证 |
| 第四阶段，保留背景并纠偏 | 查看知识来源、修改要求、暂停和恢复 | 员工读取当前版本；变更触发影响分析；暂停后停止新派发 |
| 第五阶段，多项目与资源控制 | 提交多个项目，配置优先级、并发及预算 | 排队可见；并发写入隔离；达到限制后停止派发 |
| 第六阶段，按时段或全天运行 | 设置工作时段、全天运行和异常通知 | 常驻运行、进程重启及中断恢复通过；授权与预算持续生效 |

第一至四阶段组成单项目可用版本。第五和第六阶段覆盖多项目及持续运行，完整目标在这六阶段完成后验收。各阶段都有真实页面与执行证据。

## 每个任务的执行卡

开始实现前，将任务细化为可领取的执行卡，包含目标、输入与来源版本、负责人、工作目录和写入范围、可用工具、前置依赖、产物、逐项验收条件、验收角色、放行方式、预算和阻塞上报条件。

任务状态建议表达待确认、待执行、执行中、待 Agent 验收、待人工确认、返工、已放行、暂停和阻塞。最终字段及迁移在领域设计时确定。调度器依据已提交状态决定下一步，重复调用、取消和恢复必须保持一致。

## 两个首批验收场景

自动模式使用已确认的计划，让开发员工生成文档或代码，由验收团队读取实际产物并检查全部必检项。通过后，下游交付员工自动接收已放行版本，失败则生成返工任务。

人工模式运行相同类型项目，将一个节点设为人工确认。Agent 验收通过后保持待人工状态，页面显示证据和确认操作；用户确认前，下游保持等待。用户退回时进入返工。

两个场景都要验证进程中断、重复提交、产物变化和验收缺少证据的情况。第四阶段增加中途修改要求、暂停、恢复和上下文重建用例。

## 进度和发布纪律

进度按任务状态、已通过的验收条件、真实产物与阻塞展示。排期依据实际任务规模、模型吞吐和恢复机制验证逐轮更新。每轮记录已完成项、检查证据、剩余风险和下一轮任务。

每阶段交付包含领域实现、受影响文档、对应页面以及适用的聚焦测试、录制会话、真实模型和恢复验证。已通过且未受后续改动影响的证据可复用。完整目标验收前处理现有 Windows 命令工具 ACL 故障，并核实工具组合在支持的部署环境可用。

## 逐项验收当前进展

T08–T10 已打通串行任务的逐项验收、自动放行、人工确认与检查点续跑。计划保存独立验收员工、标准、方法、证据、明确的 artifactPaths 和下游输入。每位验收员工实际使用 read 工具读取所有指定文件，并通过结构化输出提交全部检查项；缺项、重复或缺少已观察读取证据的结果记为无法验证。Host 保存规范路径、原始路径引用和解码文本摘要，在检查结束、人工放行及下游执行前核对产物。人工放行及续跑原子校验检查点和最新确认计划版本，续跑从下一任务沿用首次工作目录。

自动与人工模式均完成 OpenCodeGo deepseek-v4.1-flash 的合成文件测试。人工模式先保持下游未启动，通过工作台放行，再由另一进程续跑。工作台显示逐项报告、证据路径、文件摘要、放行和续跑操作；续跑操作准备助手草稿，需发送后执行。未配置 review 的任务仍在最终待验收；旧 review 缺少明确文件路径时停止并提示修改计划。

T11 已增加确认计划内的有界关联返工。review.rework.maxAttempts 缺省不授权，验收失败保持下游阻断；原主会话领取精确失败检查点，在原目录修复同一任务，重新独立验收。原子领取防止并发重复启动，已用次数从持久记录计算，失败或中断也计次。标准不变，旧报告保留，人工节点仍需人工放行。额度耗尽、计划变化或一般执行失败时先检查已有副作用，再修订确认计划。依赖图调度、实时推送、一般执行中断恢复、录制会话快照和 Windows 命令工具 ACL 故障处理仍未完成。验收结论来自 Agent 判断，Host 负责结构、实际读取与产物版本核对；通用检查命令与阈值的确定性执行仍需扩展。

## 主会话整合当前进展

项目计划记录 originSessionId，任务检查点记录真实父子会话地址。项目编辑、执行、纠偏和续跑准备原主会话草稿，旧未关联计划提供显式接续入口。既有子智能体目录内显示同源项目任务摘要，并复用子会话查看过程。Team 服务任务状态尚未同步，不能把产出视为完成。
