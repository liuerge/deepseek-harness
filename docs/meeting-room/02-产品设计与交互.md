# 产品设计与交互

## 信息架构

侧栏（左侧）：

1. **主助手**：唯一日常入口。单会话对话 + 右侧运行时间线。
2. **会议**：会议列表 → 会议详情。
3. **项目**：项目概览、工作目录、团队、权限、授权。
4. **任务与验收**：任务看板、执行记录、审批、验收、返工、产物。
5. **Agent 库**：角色 Agent（员工）与能力 Agent/工具分开管理。
6. **技能与 MCP**：SKILL.md 库、MCP 服务器、工具授权与导入。
7. **设置**：模型、连接、凭据、桌面/数据目录。

## 主助手页（SuperAgent）

参考 Marvis：一个主 Agent，用户只说目标。

- 顶部：目标条（项目、当前委托、预算/额度、状态）。
- 中部：对话（用户/主助手），支持补充、修订、验收。
- 右侧/下方：**运行时间线**
  - 当前步骤（拆解 → 开会 → 执行 → 审核 → 验收 → 交付）
  - 每个步骤由哪个 Agent 承接、状态（等待/进行/完成/失败）
  - 中间结果（文件、网页、检索结果摘要）
  - 关键动作的审批卡片（L2）
  - 最终产出（文件、版本、验收状态）
- 待你处理：额度批准、项目授权、待验收交付、受阻/错误，按优先级排序。

## 委托闭环（最终目标）

用户只做一件事：把目标和约束说清楚，然后不盯着。系统负责拆解、组队、执行、审核、验收、交付；用户随时回来都能看到进度、当前卡点和最终结果。

闭环的六个状态：拆解 → 开会 → 执行 → 审核 → 验收 → 交付（运行时间线按这六段呈现）。

人只在两处介入：不可逆或高风险动作的审批，以及最终验收。其余过程不打断用户——团队按名册自行推进，状态写入会话事件，随时可查。

## 角色与工位

角色是常驻的：创建一次即可反复使用，属于团队名册，不是某场会议的临时名单。每个角色有一个工位（参考 Marvis）：头像、当前状态、当前承担的任务、已产出的结果。工位让"谁在做什么"始终可见，也是看板与运行时间线的视图基础。

常驻角色不等于共享上下文：每场会议里每个角色的第一轮依旧只收到目标、材料与自己的简报（独立首轮）。

## 会议列表与详情

参考 Marvis 的"会话列表 + 运行状态"清晰度，但内容是会议：

**列表项**
- 标题、状态（待开始/进行中/暂停/待终审/已完成/受阻）
- 参与角色（头像/名称/座位）、轮次进度、当前阶段
- 最近更新、关联项目、产出方案版本

**详情**
- 阶段条：独立首轮 → 讨论 → 综合裁决 → 独立终审 → 发布完成
- 角色发言（按轮次），标注 Agent、模型、时间、状态；独立首轮不显示他人初稿
- 右侧标签：控制（开始/暂停/停止/追加轮次）、材料（原文/分类材料，只读）、方案（版本/终审状态）、成员（权限/角色）、待确认
- 争议台账：每条异议的裁决与依据
- 产出：方案版本、交付物、验收入口

## DSH 已有能力（直接复用，不重做）

- **智能体团队协作**：每个根会话可开启 Team 模式；Subagent 树 + 共享任务板；Agent 通过工具修改共享任务；任务有 pending/in-progress/completed 状态与负责人（`ui-agent-team`）。
- **Agent presets**：内置/自定义预设，创造模式创建 bundle；可作为"角色 Agent 模板"的基础。
- **审批 UI**：Host 权限请求的浏览器批准界面（`ui-approval`），覆盖工具/命令/MCP 调用；预算、验收、返工等业务审批需插件自建。
- **Conversation 渲染扩展点**：可向内建 Web Client 贡献业务行与 Chat renderer，会议消息/运行时间线可复用这套。
- **会话/子代理/工具/MCP/技能**：已有运行时，不需要自己实现 Agent 循环。

映射关系：
- 主助手 = 根会话 + 子代理调度
- 会议 = 独立根会话（Stage 0 验证创建/关联能力），角色轮次 = 该会话下的子代理 + Team 任务板 + 会议治理（新增）
- 工具审批 = DSH `ui-approval`；业务审批 = 插件审批实体与页面（预算/验收/返工）
- 会议列表/详情 = 新增插件页面（读会话事件与插件领域状态）

## Agent 两类，管理分开

### 角色 Agent（员工）
- 预置角色：项目总监、产品经理/设计师、架构师、开发、测试、审核、验收、运维、数据分析。
- 每个角色带默认能力权限与默认技能（可改）。
- 参与会议与任务；有自己的评价/履历。

### 能力 Agent / 工具
- File（文件读写/搜索）、Browser（网页）、Search（联网检索）、Computer（系统/命令，受控）。
- 作为 MCP/CLI 工具供角色 Agent 调用；不参与"会议投票"。
- 权限独立：按服务器/工具授权，默认逐次审批。

> 原则：角色负责"决定与交付"，能力负责"查与做"；不要把两者混在一个 Agent 列表里。

## 过程透明与审批

- 每一步都写事件：谁发起、用了什么工具、输入/输出摘要、耗时、是否需审批。
- 会议发言、轮次结果、裁决文本都以会话事件落库，插件库只做索引，保证"模型可见 ⟺ 可重建"。
- 关键动作（写入、删除、命令、外部发送）默认 L2 硬审批；可对单个任务显式授权。
- 预算批准、交付验收、返工属业务审批，走插件自己的审批实体与页面，不等同于工具权限审批。
- 失败/超时/空转必须明确显示原因，不静默重试。

## 技能与 MCP

- 技能：兼容 `SKILL.md`（name/description/requires/正文）；分配对象是角色 Agent；任务可追加技能。
- MCP：服务器（stdio/HTTP）注册、工具列表、按 Agent/任务授权、审批与审计；Magpie 的 MCP hub 作为预设。
- 技能只给"怎么做事"的说明，不直接执行；工具仍走权限与审批。

## 桌面体验

- Windows 桌面应用（Electron 安装包），本地数据目录，启动即用。
- 系统托盘/关闭行为、日志与诊断入口、模型连接设置。
- 不要求用户安装 Node/Python（打包内置运行时）。

## 视觉/交互边界

- 列表与时间线优先保证"可扫读"：状态色、角色头像、当前步骤、更新时间。
- 长文本（方案/意见）折叠 + 展开；中间结果摘要，不塞满首屏。
- 空/加载/错误三态明确；错误给原因与下一步。
- 深色/浅色跟随系统（沿用 DSH 主题能力）。
