# 插件清单与竞品采纳工作计划（2026-11-20）

本页合并三件事：插件家族清单与职责范围、[竞品项目工作台与智能体编辑参考](30-竞品项目工作台与智能体编辑参考.md)采纳项的分批计划、每片的验收标准与返工要求。定位：本产品线以 DSH 插件交付，改动只落在下述三个插件包内，不改 DSH 核心代码；插件消费 DSH API，需要 DSH 侧改动的条目一律不做或单独决策。

## 插件清单

产品线共三个包，`meeting-room-bundle/cordis.patch.yml` 用两条 insert 行把前两个运行时插件一次接入 profile（接入形态 B：Bundle 产品）。

| 包 | 角色 | 职责与功能范围 |
|---|---|---|
| `@deepseek-ai/dsh-meeting-room` | Host 服务端插件 | 会议编排（一场会议一个根会话，每角色轮次一个子代理）；花名册（数字员工与团队）的持久化与管理，存插件自有 SQLite（`src/store.ts`，`SCHEMA_VERSION = 6`，12 张表，zod 校验加 revision 乐观并发）；项目计划保存/确认/运行；验收评审与证据；Team 任务板镜像；员工模型路由解析与 Host 白名单授权（`src/employee-route.ts`）；面向模型的工具（如 `employee_list`、`project_plan_save`）与 `@Remote` 服务（面板数据、花名册增改查） |
| `@deepseek-ai/dsh-client-ui-meeting-room` | Web 客户端 UI 插件 | 主面板 `project-workspace`（`ProjectPage`：摘要、待办、任务看板、计划卡、花名册）；`RosterEditor` 与 `TeamPicker`；会话分区 `SessionProjects`、`SessionArtifacts`、`SessionMeetings`；会议列表与详情页；`locales.ts` 八语言文案 |
| `@deepseek-ai/dsh-meeting-room-bundle` | 组合包 | 只含 `cordis.patch.yml`，把服务端与 UI 两半组合成一条 profile 行 |

服务端消费的 DSH 能力：peer 依赖 `dsh-agent`、`dsh-llm`、`dsh-session`、`dsh-subagent`、`dsh-tools`，直接依赖 `dsh-brand`、`dsh-typert-protocol`；UI 侧经 `dsh.client.inject` 声明 10 个客户端能力包（layout、primitives、slots、workspace、session-panel 等）。experimental 组其余包（cua、forge、terminal、voice 等）与本产品线无关。

两个运行时包的 `package.json` `description` 仍停留在会议列表与会议编排，未覆盖项目工作台与数字员工，随任一代码批次顺手更新（可选项，不单独开批次）。

## 工作范围与分批计划

每片三要素：落点文件、验收标准、返工要求。A 批是纯 UI，不动持久化结构；B 批涉及插件内持久化变更，与 A 批分开提交；C 项不做或单独决策。批次顺序按改动面从小到大与依赖关系排定。

### A 批（纯 UI）

**A1 团队层级展示与头像**（30 号采纳项④）

- 落点：`client-ui-meeting-room/src/client/RosterEditor.tsx`、`RosterEditor.module.css`、`locales.ts`。
- 内容：团队从平铺列表改为卡片（头像、名称、成员数、展开/收起成员），展开区保留 29 号的模型链行，成员行带头像与模型标签；头像用客户端 primitives 固定调色板加名字首字母，颜色按 id 确定性取色，同一员工在团队与列表处一致，不引入图片资产。它是 29 号暂缓的 B 方案的具体化，A/C 两项反馈期已过，改动面最小，排第一。
- 验收标准：团队卡片可展开/收起；同一员工头像配色一致；新增文案走 `t()` 且八语言齐全（`verify-client-ui-i18n` 拦硬编码）；client `tsc --noEmit` 与 oxlint 零错误；`build:artifacts` 加 `build:check` 通过；走查探针计数（团队卡片、头像、模型链）与截图 `ui-review-20261120/15-roster-hierarchy.jpeg`，控制台零错误。

### B 批（插件内持久化变更，与 A 分开提交）

**B1 花名册缺口字段**

- 返工要求：任一兼容验证不过则不合入。

**B2 新建项目弹窗**（采纳项⑤，依赖 B1）

- 内容：弹窗字段（名称、指令）映射到既有「提出需求」提示词流程与 B1 项目字段；形态先行，做一次小设计确认，避免隐性持久化变更。
- 验收标准：弹窗字段与持久化字段一一对应，不为界面新造存储；其余门禁同 A1。
- 返工要求：同 A1。

**可选项：preset 输入改为注册表枚举**

- 内容：员工编辑器的 preset 从自由文本输入改为枚举下拉，数据来自插件内新增的只读 remote 端点，读取 DSH agentPresets 注册表，不改 DSH 侧代码。
- 验收标准：枚举项与注册表实际注册项一致；保留自由文本为兼容路径或给出迁移说明。

### C 项（不做或单独决策）

- 员工级工具权限与默认权限：权限模型在 DSH `permission-presets` 与子代理组合层，插件内没有授权面，做员工级权限需要改 DSH 侧代码，不做。
- 逐项能力勾选（Skills/MCP/Plugins）：preset 是 DSH 整包机制，逐项勾选同样要动 DSH 侧，不做；插件内过渡方案见上文可选项。
- 执行位置：执行形态固定为会话内子代理（`startActivation`），没有对应字段语义，不采纳。
- 定时任务挂项目：`packages/schedule` 是会话级语义，沿用 30 号的单独决策。
