## 决策记录

- 2026-11-15：底座从自研 Python 会议室转向 DSH（MIT，插件化、Web/Electron 桌面、工具/MCP/技能生态）。
- 现会议室（`meeting-room-studio`）保留为回退与业务规则参考；不直接迁移 UI。
- 角色 Agent 与能力 Agent 分开：角色负责"谁来决定/交付"，能力负责"怎么查/怎么操作"。
- 主助手负责拆解、调度、汇总；会议是它调度的一种协作任务，会议内部治理（独立首轮、争议、终审）不可被主助手跳过。
- 参考产品：Marvis（主 Agent + 预置能力 Agent + 过程透明 + L2 硬审批）、DSH（superagent/会话/工具/MCP/技能）、OpenCode/OpenHands/Magpie（工具与技能生态）。
- DSH 已有可直接复用的能力（2026-11-15 核对）：**智能体团队协作**（子代理树 + 共享任务板，`packages/client/ui-agent-team`）、Agent presets（内置/自定义，创造模式）、工具权限审批 UI（`ui-approval`）、Conversation 渲染扩展点。会议产品在其上实现"治理 + 会议列表/详情 + 任务验收"，不重写子代理与工具执行。
- 2026-11-15：会议内容以 DSH 会话事件为准，插件自有 SQLite 只存领域状态与索引，保证"模型可见的内容都能从会话日志重建"。
- 2026-11-15：编排模型定为"一场会议 = 一个根会话 + 角色轮次的子代理"；插件能否创建并关联独立根会话由 Stage 0 验证，失败则降级为主助手会话下的会议子代理树，治理规则不变。
- 2026-11-15：审批分两层：工具/命令/MCP 权限走 DSH `ui-approval`；预算、验收、返工等业务审批由插件自建，不复用工具审批界面。
- 2026-11-15：接入形态定为 **B（Bundle 产品）**——DSH 作底座，会议室以自有 bundle + 桌面外壳发布，内部仍由 host 插件、client 插件、bundle 三层组成；升级顺序固定为"先插件、再组合、必要时补丁、最后才 fork"。
