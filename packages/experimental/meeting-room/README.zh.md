# @deepseek-ai/dsh-meeting-room

[English](README.md) | 中文

## 概述

从主会话运行独立会议角色，并查看既有子智能体会话。角色意见与带版本的主助手结论分别留存，结论不会确认计划或调度任务。保存可复用团队和带来源的项目计划，确认后执行节点验收与检查点续跑。启用 Agent Teams 时，已启动的计划任务同步到其共享任务板，项目验收仍是放行依据。认证项目工作台读取真实记录，计划保存、确认及执行检查点通过认证流自动刷新。

## 使用本包

挂载插件，并给出子代理提供者以及会议会话与子代理使用的路由：

```yaml
- id: meeting-room
  name: '@deepseek-ai/dsh-meeting-room'
  config:
    provider: spawn
    agentOptions:
      provider: deepseek
      model: deepseek-chat
```

在你自己的编排或工具里调用 `ctx.meetingRoom.startMeeting(request, signal?, caller?)`。请求包含共享的 `requirement` 和要运行的角色；每个角色给出 `name` 与 `brief`。

角色可以从 `employee_list` 选择已保存的 `employeeId`，独立于主助手使用该员工的提供者、模型、职责和可选预设。任何参与者启动前解析全部员工引用，缺失引用会拒绝会议。捕获的员工配置写入子会话日志中的输入，模型请求记录实际使用的路由。未引用员工的角色保留继承路由。通过既有 DSH 提供者（包括 `llm-pi-ai`）配置模型连接与凭据，员工记录不含 API 密钥。插件的 `provider: spawn` 选择子代理执行提供者，不是模型厂商。

- 返回的 meetingId 标识会议流程，sessionId 标识发起主会话或专用根会话，参与角色保存在其目录中。
- 每个轮次包含角色名、子会话 id 与最终助手文本。
- `signal` 取消子代理启动与后续工作；已完成的轮次仍保留在各自日志中。

### 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `provider` | `spawn` | 每个角色轮次使用的已注册子代理提供者。 |
| `agentOptions` | 未设置 | 独立会议及未指定员工的项目任务模型路由。工具发起且未引用员工的会议角色沿用主 Agent 路由。 |
| `acceptanceMaxBytes` | `4194304` | 每个 UTF-8 验收文件的最大字节数。 |
| `modelCatalogTimeoutMs` | `10000` | 每个员工模型连接的目录查询期限，单位毫秒。 |

### 版本化项目计划

计划、设计和交付物均为所选 Git 工程目录内的真实文件。调用 `project_plan_save` 前，使用已有文件工具写入完整 UTF-8 计划，并传入 `documentPath`。保存的索引记录规范路径、工程目录和解码内容 SHA-256。确认、执行及续跑均拒绝缺失或已变更的文档以及不同工程目录。历史计划仍可读取；确认或执行前需通过新版本关联真实文档。内联执行同样要求 Git 工程目录。Host 不初始化仓库、不写计划文档、不提交或推送。

`project_plan_save` 创建或修改草稿，内容包含目标、团队、有序员工任务、验收条件和带来源的背景。创建使用版本零，修改传当前 id 和版本。每个内容版本保存团队成员和员工配置，可通过 `project_plan_list` 查询。修改保留此前各代记录，新版本需要重新确认。

工作台通过 Remote 操作记录用户确认，模型工具负责保存和读取草稿。使用 `project_execute({ planId, planRevision })` 运行已确认的最新版本，并省略内联目标、任务和团队。员工在日志可重建的输入中收到保存的来源内容、引用标识及员工配置。名册后续修改影响后续草稿。每个确认版本只允许启动一次，重复、过期或未确认版本在子代理启动前失败。中断后需检查已有操作，再建立新的经审核版本重试；自动续跑仍待实施。

既有调用者仍可提供目标和任务直接执行。计划确认校验适用于选定保存计划的执行。新运行保存执行调用者的目录，续跑沿用原目录。任务依赖调度仍待实施。工作台展示最新计划版本，计划工具可读取保留的各代记录。Host 查询当前读取全部保留计划。

任务可以通过 `review` 约定独立验收员工、逐项标准、方法、通过条件、证据、明确的 `artifactPaths`、下游输入及自动或人工放行。验收文件必须是保存的执行目录内大小已知的 UTF-8 普通文件，`acceptanceMaxBytes` 默认每文件 4 MiB。每位验收员工必须用 `read` 工具读取全部文件，并通过结构化输出逐项提交结论；结构化结果的标准标识和证据路径限于确认标准及已观察的规范产物路径。缺证据记为无法验证；诊断指出未读文件或无效引用，并保留验收员工提交的状态和观察。报告保存 Host 观察到的解码文本 SHA-256 和规范路径，验收后、人工放行前及下游执行前重新核对。自动节点全部通过后继续，人工节点等待工作台放行，再用 `project_execute({ projectId, expectedCheckpoint })` 从下一任务沿用原目录续跑，检查点只允许领取一次。计划或文件变化会拒绝放行或续跑。缺少明确路径的旧节点保留 `awaiting-acceptance`；没有 `review` 的计划保留最终人工验收。

验收失败保留报告并阻断下游。确认计划中的 `review.rework.maxAttempts` 授权该任务正整数次的有界返工，省略则不授权。原主会话对最新 `acceptance-blocked` 检查点调用 `project_execute({ projectId, expectedCheckpoint })`。工具启动前原子领取 `reworking`，将本次返工关联到失败检查点。原员工收到失败报告和不变的标准，沿用原目录修复，再由新子会话独立验收。旧报告仍可查询，人工节点仍需工作台放行。失败或中断也消耗次数；其他失败或中断状态不能通过此方式续跑，需要先检查已有操作。新计划版本阻止旧返工领取。工作台展示确认的上限和已用次数，返工操作准备主会话草稿，不自动发送。

派发下一项任务前，执行器检查主会话待处理的用户输入，保存 `awaiting-direction` 并交还主助手，不中断当前员工回合，也不丢弃排队消息。处理新输入后，原主会话可领取精确检查点继续未变更的确认计划；需求变化则修订并重新确认。该状态的检查点索引指向下一项未启动任务，续跑不重复已完成工作。内联执行保存 `interrupted`，不提供检查点续跑；检查已有工作后，为剩余任务保存确认计划。续跑时仍有用户输入排队则返回 `PROJECT_DIRECTION_PENDING`，不推进检查点。

### 可复用员工与团队

认证的 `projectRoster` 服务为工作台编辑器提供已注册连接目录及带版本核对的员工/团队保存。员工保存要求提供者路由已注册，模型 id 可以不在候选目录中。连接注册不代表凭据验证通过。模型目录按路由设置查询期限，取消或插件卸载会结束等待，失败按路由明确返回；适配器不能取消的底层目录请求仍由提供者负责。保存名册不会确认计划或启动模型工作，已确认计划保留捕获的员工配置。

`employee_list` 返回本 Host 保存的员工及团队模板。`employee_save` 保存姓名、职责、显式提供者和模型，以及可选的已注册 DSH `preset`。`team_save` 保存包含不同既有员工 id 的团队。创建时省略 id 并使用 `expectedRevision: 0`，更新时传当前 id 和版本。过期保存返回 `PROJECT_ROSTER_STALE`。文件数据库跨重启保留配置，将已有项目数据库升级到 schema 版本 6 并保留历史。

项目任务传 `employeeId` 后使用对应员工的模型、职责和可选预设。省略预设时沿用调用者组合。传 `teamId` 后，每项任务必须选择该团队内的员工。执行前解析全部任务引用，并保存本次员工和团队版本。后续名册修改影响后续运行。未传员工 id 的既有任务保持原有行为。

名册工具和工作台目录作用于整个 Host。模型路线和预设必须在运行组合中可用，不可用配置由子代理运行时在启动时报告。员工配置的有效工具能力由预设和现有工具审批系统决定。员工删除、活动投影和逐技能编辑仍待实施。

### 项目执行

认证的 `projectTeamContext` 服务通过 `select` 捕获主会话的规划默认团队，核对界面显示的选择、团队及员工版本，`current` 读取保存的快照。选择存入项目数据库，不派工、不启用共享看板、不授予工具权限、不确认计划。后续名册修改不改变已选快照。明确传空团队会以新版本清除默认选择，子员工不能修改父会话选择。

必需的 `systemPrompt` 服务将这些默认配置写入主助手实际请求所用的运行上下文日志。员工读取自己的任务指令，不接收这段根会话专属上下文。清除选择时明确写入无默认团队，替代此前选择。仅实际发给模型的上下文进入 Session 日志，当前规划偏好由业务数据库保存。客户端入口见[工作台界面](../client-ui-meeting-room/README.zh.md)。

`project_execute` 接收目标和有序任务，每个任务包含 `role`、`instruction` 和 `acceptance`。员工通过配置的子代理提供者使用发起会话的工作目录和工具组合。每个任务收到前一个员工的交接结果及共同目标。执行返回 `awaiting-review`，调用者检查产物后进行交付验收。子代理以非完成状态结束时，后续任务停止并报告带错误码的失败。

`project_records` 按新到旧读取调用会话的检查点，`limit` 为显式正整数。将 `databasePath` 配置为文件可跨重启持久保存。索引保存计划、任务状态、子会话引用和交接结果。子会话日志保留工具调用与提示词。进程中断后留下的运行中检查点需要在重试前核查。续跑和返工保留原执行标识。

单次调用内任务串行执行。不同调用共享发起者的工作区，需要协调。取消停止剩余任务并释放当前子代理，文件和外部工具操作可能已经生效。自动重启恢复、项目级暂停和完整知识检索仍待开发。查询按条数限制，交接长度取决于员工输出限制。

### Team 共享任务

发起根会话启用 Agent Teams 时，确认计划在任何员工启动前为每项任务创建一个共享任务。任务包含员工、指令、验收文本和稳定标记，并依赖前一项任务，因此未放行节点继续阻断下游。项目数据库保存关联及最近观察到的版本。被派发的员工会话通过 Team 服务领取任务；项目验收仍是放行依据。

自动放行在项目记录 `acceptance-passed` 后完成任务。人工放行保持 `in_progress`，直到下一次经确认的续跑同步。验收失败、返工、阻塞或中断时任务保持 `in_progress` 并保留负责人，真实原因由项目检查点记录。重复启动复用已持久预留的执行，并按标记吸收既有任务，不重复创建。

关联员工先预留子会话身份，在 `agent/pre-step` 等待 Team 领取成功；领取前不发送模型请求或执行工具。不支持预留身份的提供者返回 `PROJECT_TEAM_GATE_UNAVAILABLE`。看板人工编辑、释放、改派或外部完成均按保留版本及负责人核对，不当作项目自身操作吸收；部分关联重试也保留原关联版本。并发准入限于本 Host 实例，卸载等待关联、放行同步和员工收尾后再关闭存储。不提供跨进程互斥或崩溃恢复。工作台人工放行核对产物，后续执行在派发下游前再核对 Team 冲突。

启动时 Team 模式关闭会记录 `teamLink: disabled` 并只运行项目记录；Team 服务缺失记录 `unavailable`。关联后关闭 Team 模式会使下一次派发或续跑以 `PROJECT_TEAM_DISABLED` 停止；重新启用并检查看板后再继续。任务被删除、提前完成或缺失时停止执行并要求检查。既有未关联执行不补造历史关联。可选接入位于 `src/team-link.ts`，关联表由 `src/store.ts` 管理。

## 实现说明

<a id="understand-the-implementation"></a>

<details>
<summary>实现细节——点击展开</summary>

startMeeting(request, signal, caller) 使用指定主 Agent 作为参与角色的父级。不传 caller 时拥有新根会话。角色子会话通过 caller 方式交付，提示词只含目标与自身角色。未完成输出阻止后续角色。取消和插件卸载会释放活跃角色，并等待执行收尾后再关闭存储。

`rolePrompt` 输出共享目标、角色名、简报和可选的员工配置快照，不包含其他角色的输入或输出。需要读取此前初稿的讨论轮必须显式包含这些内容。

SQLite schema 版本 5 保存会议关联、角色输出、不可变结论版本和 Team 任务关联。既有会议和轮次继续保留，未关联历史行不推测所属会话。最终检查点保存失败会报告记录状态不确定，重试前需检查。

## 模型体验

### meeting_start 工具

#### 模型看到什么

模型向 meeting_start 提供目标和角色简报，收到包含流程、会话身份及角色输出的 JSON。meeting_records 返回保留的结论版本。meeting_record_decision 追加发起主助手的结论，但不确认计划。启动角色需要配置的审批能力，没有答复通道时拒绝执行。

#### Token 影响

声明会向能看到该工具的请求加入一份小 schema；结果按角色各占一段。

#### KV 缓存影响

声明稳定，不改变每次调用的前缀。审批增加的是用户交互，不是模型上下文。

### 角色提示

#### 模型看到什么

每个角色收到一条用户消息：`会议目标：<requirement>`、自己的角色名、简报和可选的员工配置快照。该请求中不会出现其他角色的提示或初稿，因为 spawn 子会话从空日志开始。

#### Token 影响

每个角色一次请求，大小由会议目标、简报和可选员工配置决定；角色提示不新增工具声明，也不新增系统提示段落。

#### KV 缓存影响

每个子会话从空日志开始，角色之间没有可共享的缓存前缀，首轮按完整提示计费。将来需要读取他人初稿的讨论轮会扩展这段文本，计费方式随之改变。

### 项目工具

#### 模型看到什么

执行工具提供目标、有序说明和验收条件，返回项目 id、待审核状态和最终交接结果。记录查询返回调用者的检查点，名册查询返回本 Host 的员工和团队记录。员工职责及使用版本进入员工提示词。按计划执行还包含该版本的背景原文及来源引用。员工提示词包含目标、任务和前序交接结果。验收员工还收到确认标准、作者交接、观察到的产物版本及子会话专属结构化输出工具。续跑员工在日志可重建的输入中收到已放行报告。

#### Token 影响

两个项目 schema、三个名册 schema 和两个计划 schema 增加固定上下文。员工请求包含任务与交接文本，查询增加请求的检查点内容。

#### KV 缓存影响

工具结果追加到调用会话历史。每个员工启动新的子会话。返工员工还会在日志输入中收到失败报告与返工引用。

### 已选团队上下文

#### 模型看到什么

主助手收到包含捕获团队及员工的必需运行上下文，并被要求通过 `meeting_start` 收集所选员工意见、通过 `meeting_record_decision` 留存主助手综合结论，再准备可确认的计划。用户纠偏要求检查真实执行记录，并在需要时修订计划。要求的 n8n 验证应作为测试员工任务，由员工使用可用命令工具触发并提供真实执行证据；工具或权限不可用时明确报告阻塞。明确清除时说明当前无默认团队。子员工不接收这一节。Session 通过既有上下文快照机制记录实际渲染内容。

#### Token 影响

选择及清除不新增模型请求。渲染快照包含所选员工配置，Token 大小随其文本变化；选择未变时沿用既有运行上下文复用策略。

#### KV 缓存影响

稳定工具声明及系统段落不变，偏好变化更新已记录的运行上下文后缀；已确认计划的内容仍独立保留。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 只有独立的首次轮次；讨论、异议、裁决与发布尚未实现。
- 轮次串行执行；并行轮次需要先明确工作目录与负责人。
- 后续讨论轮次和由会议结论自动调度任务尚未实现。
- 会话菜单读取实际关联会议；没有已知发起会话的历史记录仅保留索引。
- Team 关联只按计划顺序建立依赖；并行依赖、多项目队列和跨进程恢复仍待开发。
- 直接在 Team 看板修改负责人或依赖不会被项目自动核对；任务被删除、提前完成或缺失时停止项目执行并要求检查。
