# @deepseek-ai/dsh-experimental-client-ui-meeting-room

[English](README.md) | 中文

## 概述

此插件将项目工作与会议关联到主会话。项目进度仍在侧边栏工作台中查看。会话页头更多菜单可准备会议请求，或打开该会话发起的真实会议，不再提供独立会议侧边栏入口。参与角色意见与带版本的主助手结论分别展示。

<a id="use-this-package"></a>
## 使用本包

从主会话页头更多菜单选择让主助手安排会议，在该会话准备未发送请求，并保留已有草稿。本会话会议记录打开已保存的讨论、角色会话链接、结论版本和后续行动。记录结论不会确认项目需求。

项目工作台首屏是状态看板：先显示由目标、计划版本、团队、确认状态与当前阶段组成的属性行，再是五列（待开始、进行中、待验收、已通过、受阻），列头带任务数量。卡片只显示员工、状态、任务角色、Team 任务关联、产物 chip 与导航动作；任务指令、验收条款、验收报告与交接记录在看板下方的整幅面板展开。看板可展开为视口大小的对话框，列布局与已打开的详情保持不变。有需要用户处理的动作时单独显示待处理块。已保存的员工与团队位于看板与计划之后。编辑计划、按保存计划执行、提出调整及放行后续跑，均在关联的主会话准备草稿。无法确定主会话的旧计划提供明确的接续草稿入口，要求助手保留内容、保存关联本会话的新版本并重新确认。

可在工作台直接配置员工：填写职责、选择已注册模型连接、输入模型 id，并可选填写 DSH 预设。每名员工独立使用自己的路由，兼容网关可填写自定义模型 id。勾选已保存员工创建或编辑可复用团队。保存核对显示版本，失败时保留输入，不启动模型工作、不改变已确认计划。连接目录独立于项目记录加载，不代表凭据已验证；凭据通过既有模型提供者设置配置。从工具预设下拉框选择团队模式，核对每名员工的路由，并为此主会话选择已保存团队。尚未绑定会话时先选择工作区。选择团队后，团队 chip 才显示在预设旁；已开始的会话通过页头操作进入。选择先捕获显示的版本，再启用共享看板，不确认计划、不启动工作。无法确认看板启用时保留已保存选择，供核对并重试。清除偏好保留既有任务和看板模式。

模型连接通过账号菜单 → 设置 → 模型 → 添加模型提供商配置，可选目录厂商或自定义模型 API。员工下拉框列出已注册路由，不枚举全部支持的厂商。员工原连接未注册与连接列表为空分别提示；配置路由后刷新工作台。配置模型连接按钮可直接打开此模型分区，并保留员工草稿。保存设置和 Host 重连会自动刷新连接目录；发现期间再次变更配置会补读一次。

任务执行链接使用已记录的直接父子身份打开现有子智能体会话。根会话既有子智能体目录还会显示同一检查点来源的项目任务页脚。产出数量与验收分别表达，此页脚显示 Team 任务标识与状态，但不修改它们。

| 控制 | 效果 |
|---|---|
| 确认此版本 | 确认精确的最新计划版本。 |
| 确认验收并放行 | 重新核对文件并放行通过检查的人工节点。 |
| 继续下游任务 | 在原主会话准备携带精确检查点的续跑草稿。 |
| 让主助手安排返工 | 在确认次数内准备失败检查点的返工草稿，保留旧报告，任务入口打开最新执行会话。 |
| 刷新进度 | 重新读取项目目录或所选会话的会议。计划、确认及项目检查点保存后也会自动刷新。 |

<a id="understand-the-implementation"></a>
## 理解实现

会话顶部在“对话”和“轨迹”旁提供“成果”。列表展示最新计划版本关联的真实磁盘文档，以及每项任务最新独立验收报告实际观察的文件。所有文件行复用标准右键菜单，包括可用的下载和本地打开操作。确认精确核对版本和已观察的计划文件哈希，不启动工作。缺少文件的旧计划显示未关联提示并禁止确认。列表不嵌入预览、不创建虚拟文档，不从计划路径或正文猜测产物，也不保证此前观察的交付文件仍未改变。Host 要求 Git 工程目录；主助手使用既有工具写文档，提交历史由 Git 管理。

插件挂载 Host projectDashboard、projectRoster 和 projectTeamContext Remote，并通过可撤销副作用注册面板、sessionHeader 菜单与既有子智能体页脚。切换会议所属会话会取消前次查询，迟到结果不会写入其他会话。卸载时取消并等待未完成查询。模型工作仅在用户发送准备好的草稿，或主助手调用工具后启动。

SessionMeetings 渲染真实 Host 记录。ProjectPage 与 SessionProjects 共享项目检查点来源。旧原型会议组件不再挂载，也不提供产品数据。

<a id="model-experience"></a>
## 模型体验

### 主会话草稿

#### 模型看到的内容

项目草稿包含 `projectId`、`expectedCheckpoint` 等引用，会议草稿请求使用 `meeting_start` 和 `meeting_record_decision`，仅在发送后进入普通用户输入。读取菜单和报告不产生模型请求。

#### Token 影响

仅发送的草稿内容增加用户输入 token。Host 插件负责工具声明和员工提示词。

#### KV Cache 影响

发送的草稿追加到会话历史，已有草稿按追加方式保留在准备请求之前。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- 会议需要手动刷新。计划和检查点通过本 Host 的流接收失效通知，其他进程的写入不会触发通知。
- 会议串行执行独立首轮；自动辩论、需求确认及由结论自动调度任务尚未实现。
- 执行记录中保存直接父子地址后才提供任务链接。未关联的历史会议索引继续保留，不推测发起会话。
- 工作台显示 Team 任务关联，但不提供直接编辑；负责人或依赖变更请在 Team 看板操作。
- 主会话调整会准备修订计划，工具执行中的即时纠偏和自动返工尚未完成。
